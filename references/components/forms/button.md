# Button
Updated 2026-07-23 to match Figma "IDS_WEB — Internal Design System", node 4901:33217 (`get_design_context`) — supersedes the old 5-variant/opacity-dimmed spec below.
- **Exactly 6 variants, a closed set — never invent a 7th.** `primary` (solid `#141ED2`), `secondary` (tint fill `#F6F8FF`, `#14142A` text — solid, not bordered), `outline` (transparent bg, `1px solid #BEC2F4` border, 8px radius), `pill` (same as `outline` but pill/9999px radius), `ghost` (transparent bg, no border, pill radius), `textLink` (transparent, regular-weight label, 2px icon gap, pill radius — moot since there's no fill). This is the full set in the Figma frame — there is no `danger`/`success`/other color variant, and none should be added speculatively "by analogy." If a task seems to need one, ask first rather than adding it.
  - **Mandatory auto-mapping rule**: when converting an input file (uploaded wireframe, screenshot, or legacy code) whose buttons use a style outside this set of 6 — a red "delete" button, a green "approve" button, an outlined-vs-filled distinction that doesn't match one of the 6, etc. — map it onto the **nearest of the 6 declared variants** automatically. Do not preserve the foreign variant as-is and do not invent a matching new one. In practice: a destructive/affirmative action that used to get its own hue now reads through **emphasis** instead of color — `primary` for the one dominant action in a row, `outline`/`ghost`/`textLink` for lesser actions — the same "one primary per row" logic already governs every other screen.
  - `outline` and `pill` are the same color treatment at two different radii — don't treat them as different hues.
  - Colors are `var(--color-*)` references into `tokens/colors.css`, not hardcoded hex — required by color-rules.md's 2026-07-23 rule for new/updated components. Several Figma hex values (hover/pressed, disabled neutrals, the loading tint, the loading text) don't have an exact declared alias; those resolve to the nearest available token (alias or raw scale) instead — see the Color Token Coverage report on the Button update for the exact similarity% of every non-exact row. `outline`/`pill`'s border and `secondary`'s hover background both land on the same nearest token (`--color-primary-200`) as a couple of other rows — an accepted, reported deviation, not a bug.
- Sizes: `small` (32px), `medium` (40px), `large` (48px) — `small`/`medium` share a 14px/lh21/tracking-0.28px type scale, `large` steps up to 16px/lh24/tracking-0.32px. Horizontal padding is a flat 16px across all three sizes (only height/font change) — this is a genuine Figma finding, not a simplification.
  - This exact type scale doesn't match any of the 12 declared scales in `typography-rules.md` (closest, `--type-button-*`, forces `uppercase` + 1.25px tracking, which the Figma spec explicitly does **not** use) — sizes/tracking are Figma-literal by design; only `font-weight` is token-backed (`--font-weight-semibold` / `--font-weight-regular` for `textLink`).
- Label text is sentence case, never uppercase (see cross-cutting rule) — `textLink` additionally uses **regular** weight (400) where every other variant is semibold (600).
- Icon-only mode (no `children`, exactly one of `iconLeft`/`iconRight`): button becomes a fixed square (or circle, for `pill`/`ghost`) matching its height, icon centered, no visible label. `textLink` does not support icon-only or `iconRight` per the Figma symbol set — text-only and icon-left only.
- Icon-only buttons may take a `tooltip` string, shown centered above the button on hover only (never on text+icon buttons): white-90% bg (`rgba(255,255,255,0.9)`), `#041557` text, 4px radius, `0px 2px 4px rgba(4,21,87,0.1)` shadow — a distinct, lighter treatment from the DS's own dark-navy `Tooltip` component; don't conflate the two.
- `hover`: `primary`/`secondary` swap to a darker/tinted solid fill; `outline`/`pill` swap the border to solid brand `#141ED2` (fill stays transparent); `ghost` gets a faint `#F4F5FF` fill and — icon-only specifically — recolors its icon to brand blue; `textLink` underlines. Never invent a 2nd hover treatment per variant.
- `disabled` = a **fixed neutral treatment**, not a dimmed variant: filled variants (`primary`/`secondary`) drop to flat `#EFEFEF` bg + `#7F7F7F` text; bordered variants (`outline`/`pill`) keep transparent bg but mute the border to `#9AA1BC` + `#7F7F7F` text; borderless variants (`ghost`/`textLink`) just mute text to `#7F7F7F`. This replaces the previous "opacity: 0.4 dimmed" rule — that no longer matches the Figma spec.
- `loading` = 16px spinner in the `iconLeft` slot, label stays visible (e.g. "Đang lưu"), button implicitly non-interactive. Background/text also swap to a **dedicated loading treatment**, not the variant's own hover/disabled colors: `primary` → `#BEC2F4` bg / `#14142A` text; every other filled/bordered variant → `#DADDFA` bg (`outline`/`pill` keep a `#BEC2F4` border) / `#858BE9` text; `textLink` keeps a transparent bg with `#858BE9` text only.
- Only one `primary` per row (cross-cutting rule, see `references/component-rules.md`).
