# Badge vs. Tag — pick by intent, not by look
These are easy to confuse; they're not interchangeable.
- **`Badge`** = status indicator: pill shape (`border-radius: 9999px`), no border, small leading dot for state badges (`dot` prop), and no dot when it's a closable filter chip (`onClose` present) instead — used for "what state is this record in" (Đang làm việc / Chờ duyệt / Nghỉ việc / Hoàn thành / Thử việc).
- **`Tag`** = category/label chip: rectangular (`border-radius: 4px`), always has a 1px border in the same hue family as its text/background, no leading dot — used for "what category/filter does this belong to" (Kế toán / CNTT / Nhân sự).
- Never use `Tag` to show a record's status, and never use `Badge` for a filter/category chip.
- **`Badge` size**: `size?: 'small' | 'medium' | 'large'`, same naming as `Button`'s own size prop. `small` (`2px 8px` padding, `10px` font, `5px` dot), `medium` (`3px 10px` padding, `11px` font, `6px` dot), `large` (`4px 12px` padding, `12px` font, `7px` dot) — `large` is the prop's default when `size` is omitted.
- **Size by placement (updated 2026-08-24) — pick by where the badge sits, not by habit:**
  - **`medium`** — inside a `Table` status column/cell (any dot+pill status cell per `references/components/data/table.md`), and any other dense/inline list context (e.g. a table-adjacent count pill like a "SL Mã…" column). Table rows are the one place `large`'s bigger footprint doesn't fit the row height/density — pass `size="medium"` explicitly there since it's no longer the default.
  - **`large`** — inside a page header title row (`PageHeader`'s `badge` prop, see `references/components/layout/pageheader.md` — the status badge next to a detail page's title) and inside a card/section header title (`DrSectionTitle`'s count badge, see `references/components/overlay/dr-section-title.md` — e.g. "NVTT Nội bộ **8 mã**"). These sit next to a larger heading (`Subtitle 1`/`page-title` scale text), so the badge needs the bigger footprint to hold visual weight against it — this is exactly why `large` is the default, since both of these are the more common placements.
  - `small` isn't yet tied to a specific placement rule — reach for it only where `medium` still reads too heavy for the surrounding density (e.g. a very compact inline chip list), and note the choice inline since there's no standing precedent for it yet.
  - Gap handling for a placement not covered here: don't guess — flag it and default to `medium` if the surrounding text is body-scale, `large` if it's heading-scale, then ask if genuinely ambiguous.
