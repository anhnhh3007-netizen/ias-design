# DCard

Header+body detail card — source at `components/display/DCard/`. Distinct from `Card` (whose `title`/`footer` are optional): DCard's header/body pair is **mandatory**, not a configurable slot.

- **Always exactly two parts, in this order: `d-card-header` then `d-card-body`.** Never render `d-card-header` without a following `d-card-body`, and never put body content directly inside `.d-card` unwrapped — every piece of body content, table included, is a child of `.d-card-body`. This was a real gap found in `templates/ias-xem-chi-tiet/XemChiTiet.dc.html` before this rule existed (its "Lịch sử thay đổi" card put `.table-wrap` directly under `.d-card`, skipping `.d-card-body`) — fixed as part of adding this component.
- **Surface**: `12px` radius, `1px solid var(--color-border-default)`, `var(--color-bg-surface)` background — same card-surface spec as `Card`/`ListPanel`, `overflow:hidden` so the header/body corners stay clipped.
- **Header (`d-card-header`)**: flex row, `16px 20px` padding, title left / chevron toggle right (`justify-content:space-between`). Title is plain `14px/600` text (`--color-text-primary`) — not mapped to a `.hcm-*` scale, this is DCard's own internal convention, same exemption class as `Table`'s header text or `PageHeader`'s title. `headerExtra` (e.g. a count `Badge` — "8 mã") sits immediately after the title, same flex group.
  - **Chevron toggle is mandatory, on every `DCard`, no exceptions (updated 2026-08-21 — reverses an earlier "collapsible is opt-in" draft of this rule).** The whole header row is always clickable (`cursor:pointer`) and a 28×28px chevron button (`expand_less` open / `expand_more` collapsed) always sits at the far right. There is no static/non-collapsible variant — a `d-card-header` with no toggle icon is a violation, the same way a missing title or a missing `d-card-body` would be. This matches `XemChiTiet.dc.html`'s own reference cards, which were always collapsible; the earlier "opt-in" framing was itself the deviation, introduced when `Mapping NVTT`'s simpler cards were built without one — those are exactly the cards that need retrofitting, not evidence the toggle was ever optional.
  - **`title` has no empty state.** Because the header is mandatory, there's no such thing as a DCard with a blank or omitted title — if the source input (an uploaded wireframe, a business description, or a data model with no explicit card caption) doesn't spell one out, **infer it from context** rather than leaving `d-card-header` empty, rendering it as a bare icon, or dropping the header to work around the missing text. Inference order:
    1. **Body shows one record's own fields** (the field-grid shape) → `"Thông tin " + <entity/section name>` — e.g. `mapDetailHeaderTitle`'s `'Thông tin ' + MAP_TITLE[anchorKey]` → "Thông tin NVTT Pháp luật".
    2. **Body shows a related list/table belonging to another entity** (the Table shape) → the entity name alone, paired with a count `Badge` in `headerExtra` — e.g. the Mapping NVTT cross-reference cards: `MAP_TITLE[gk]` + `"N mã"`.
    3. **No entity/section name is derivable from context at all** (last resort only) → a generic but still-descriptive title such as `"Thông tin chi tiết"` — never a placeholder like "Card" or "Untitled", and never truly empty.
- **Body (`d-card-body`)**: `0 20px 20px` padding (no top padding — the header's own bottom padding already spaces it from the title). This is a **flexible content slot**, not a fixed layout container — DCard itself does not impose a grid or any structure on `children`. Two sanctioned shapes cover the vast majority of real usage:
  1. **3-column `Field` grid** (the default for read-only record data — "Xem chi tiết" pages, mapping detail screens): an inner `.field-grid` div (`display:grid;grid-template-columns:repeat(3,1fr);gap:22px 24px`) holding `Field`s, `full` spanning a field across all 3 columns (see `references/components/display/field.md` — Field doesn't own the grid itself, whatever wraps it does, and here that's `d-card-body`'s inner `.field-grid`, not `d-card-body` directly). Mark the anchor/primary identifying field `full` too if it would otherwise sit alone in column 1 with empty cells beside it — a single non-full item followed by a `full` item leaves two blank grid cells, not a clean full-width row (this exact bug was found and fixed in `can-cu-xu-phat-ias-redesign.html`'s Mapping NVTT detail page).
  2. **`Table`** for tabular content (e.g. a cross-reference list, a change-history log). **Must be the real `Table` component (`components/data/Table`) — never a bespoke `<table>`/`.modal-table` reimplementation.** This was a real violation found in the wild (`can-cu-xu-phat-ias-redesign.html`'s `mapCrossRefTableHTML` built its own ad-hoc table markup instead of reusing `Table`) — DCard formalizes the fix: if the body needs a table, it's `Table`, full stop. `Table`'s own square-corner/borderless-wrap rule (`references/components/data/table.md`) still applies even inset inside `d-card-body`'s padding — only the outer `.d-card` keeps the 12px radius + border.
     - **Table section toolbar (added 2026-08-26): put a `ToolbarSimple` directly above the table, as the first child of `d-card-body`** — same fixed anatomy as the page-level `ToolbarSimple` (`references/components/data/toolbarsimple.md`): search → "Tìm kiếm" → "Tìm kiếm nâng cao" (a compact `FilterCard`-style row scoped to this table's own columns) → trailing "Cài đặt bảng" (`ColumnPicker`, scoped to this table's own columns — see `references/components/data/columnpicker.md`, including "every option must render a real column"). Render at `.btn-sm`/`.btn-icon-sm` scale (32px controls) to match the card's own density, not the page's 40px scale. Same rule, same reasoning, as `Drawer`'s own table sections (`references/components/overlay/drawer.md`'s "Table section toolbar") — a `DCard` table body is "the same kind of flexible content slot" as `Drawer`'s, so it gets the same toolbar treatment. Reference implementation: `templates/ias-xem-chi-tiet/XemChiTiet.dc.html`'s "Lịch sử thay đổi" card.
  - Any other block content (a paragraph, a nested `Alert`, a small chart) is fine too — "flexible" means DCard doesn't gatekeep content type, only that *if* the content is field-style data or tabular data, it must use the matching sanctioned shape above rather than inventing a third pattern.
- **Reference implementation**: `templates/ias-xem-chi-tiet/XemChiTiet.dc.html` — its "Thông tin căn cứ xử phạt" card is the field-grid shape, its "Lịch sử thay đổi" card is the table shape; both always collapsible per the mandatory-chevron rule above.
