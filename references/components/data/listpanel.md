# ListPanel
Formalizes the `.list-panel` wrapper every "danh sách" screen already used ad hoc (see the List-screen layout convention in `references/component-rules.md`) — source at `components/data/ListPanel/`.
- Structural: flex column, `16px` gap, three fixed slots in order — `toolbar` (`ToolbarSimple` ⇄ `FilterCard`, caller renders exactly one) → `table` (a `Table`) → `pagination` (the full `.pagination-bar` row: count + `Pagination` + page-size + page-jump). `ListPanel` does not manage the toolbar/filter toggle itself — that stays the caller's state.
- **Carries its own card surface**: white bg (`--color-bg-surface`), `1px solid --color-border-default`, `12px` radius, `16px` padding — matching `templates/ias-danh-sach-chuong-trinh/DanhSachChuongTrinh.dc.html` exactly. `Table` still renders its own shadowed card *inside* this one — a deliberate card-in-card look, standardized as of 2026-07-31, not a bug to flatten out.
- **Id is required**, following `ias-{domain}-list-panel` (e.g. `ias-nvttpl-list-panel`) — see the List-screen layout convention above for the full containment rule.
- Propagated to `DanhSachChuongTrinh.dc.html` at the same time (per the Propagation rule in `references/component-rules.md`) — its `.list-panel` already matched this exact spec, so no markup change was needed there, only confirming it as the reference. `US-001-nvtt-pl-danh-sach-ias-design.html` (a delivered screen outside `templates/`) was updated to match (`.list-panel` now carries the same bg/border/radius/padding, via `var(--color-bg-surface)`/`var(--color-border-default)` since that file already defines those tokens itself).
