# AppHeader
**Excluded from every screen by default (`SKILL.md` Step 3)** — it's no longer part of the standard shell (`AppSidebar` + `PageHeader` only). Only place `AppHeader` when the user explicitly asks for a top search/notifications/avatar bar on a specific screen; don't add it back when converting an uploaded wireframe just because the source had one.
- If/when it is used, what's evidence-backed from the component's own sample (`components/navigation/AppHeader/appheader.card.html`): search field (left, capped `max-width: 400/420px`) → flexible spacer → a small group of transparent/ghost icon-only buttons, 36×36px, square-ish 8px radius (message, notification-with-badge) → avatar, always last, nothing after it. Notification badge (small red circle, count) sits top-right of the bell icon only when `notificationCount > 0`.
- ⚠️ Note this evidence-backed structure (search + icon-buttons + avatar) does **not** match an "outline → secondary → primary → icon(more_vert), max 4 buttons" pattern — if a future request wants that pattern specifically, it requires editing `appheader.card.html` + `AppHeader.d.ts` themselves, not just this rule doc.
