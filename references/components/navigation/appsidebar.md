# AppSidebar
- Two widths only: mini (64/96px, icon-only, centered) and expanded (up to 248px, icon+label, hover-triggered — width transitions on `:hover`, it does not require a click-to-pin). Never a third fixed-width state.
- Fixed vertical order: logo → search (when present) → nav item list (scrollable) → optional pinned footer (settings/avatar). Don't reorder the logo below the nav list, and don't let the nav list scroll region swallow the logo or footer.
- Active state is a **translucent white fill** (`rgba(255,255,255,.10–.12)`), never a border or a solid opaque color — this is what visually distinguishes "active" from the dark navy base at a glance.
- Group headers use a single `arrow_drop_down` chevron that rotates 180° open/closed; expandable tree nodes use `add`/`remove` glyphs instead of a chevron — don't mix the two affordances for the same interaction type.

## Tree data shape (up to 3 levels)
- The nav tree is a flat top-level list; each item is one of three shapes — a **plain leaf** (no children, e.g. `Hồ sơ phê duyệt`), a **2-level group** (children, none of which have their own children), or a **3-level group** (children where at least one child itself has children, e.g. `Pháp luật › NVTT Pháp luật › Căn cứ xử phạt`). Don't force a uniform depth across the whole tree — most groups in the real IAS menu are 2-level, only a few are genuinely 3-level.
- **Level-2 items come in two shapes, and the shape is per-item, not per-group**: a child with no children of its own renders as a **plain leaf** (`fiber_manual_record` bullet, regular weight, `#8B8FBD`, no toggle affordance) sitting directly under the level-1 group at one indent step; a child that has its own children renders as an **expandable node** (`add`/`remove` glyph, `font-weight:600`, toggles its own nested list on click) — the same level-1 group can mix both in one list (see `Pháp luật`: `Văn bản pháp luật` is a plain leaf, `NVTT Pháp luật` is an expandable node, both siblings under the same group). Never make a childless level-2 item expandable "for consistency" — it has nothing to expand into.
- Level-3 leaves are always plain (bullet, no further nesting) — the tree does not go deeper than 3 levels. If a real menu needs a 4th level, that is a sign the branch belongs in a `Tabs` bar inside the page instead (see below), not a deeper sidebar tree.
- **Canonical real menu** (IAS — NVTT/compliance module): `Trang chủ`, `Đồng bộ dữ liệu văn bản`, `Pháp luật` (`Văn bản pháp luật`; `NVTT Pháp luật` → `NVTT Pháp luật`, `Căn cứ xử phạt`, `NVTT chỉ đạo từ CQBN`), `Nội bộ` (`Văn bản nội bộ`, `NVTT Nội bộ`), `Mapping NVTT` (`Mapping NVTT Pháp luật`, `Mapping NVTT Nội bộ`, `Mapping Căn cứ xử phạt`), `Hồ sơ phê duyệt`, `Thư viện` (`Tổng hợp NVTT`; `Thư viện NVTT` → 3 leaves; `Thư viện mapping` → 3 leaves), `Cẩm nang NVTT`, `Bóc tách văn bản`, `Kho tài liệu`, `Danh mục NVTT` (`Cơ quan ban hành`, `Loại văn bản pháp luật`, `Loại văn bản nội bộ`). This is the literal reference tree in both `AppSidebar/appsidebar.card.html` and `templates/ias-layout/IasLayout.dc.html`'s `NAV_TREE` — extend it there, don't fork a second copy elsewhere.

## Level-3 → Tabs escape hatch (per-screen choice, not a sidebar limitation)
- A screen sitting on a 3-level branch **may** truncate the sidebar to level 2 and expose the level-3 siblings as a `Tabs` bar directly under `PageHeader` instead of leaving them in the tree — e.g. the `Căn cứ xử Phạt` screen collapses `Pháp luật` to just `Văn bản pháp luật` / `NVTT Pháp luật` in the sidebar, then shows `NVTT Pháp luật` / `Căn cứ xử phạt` / `NVTT chỉ đạo từ CQBN` as tabs in the content area.
- This is a **per-screen composition decision** driven by how central that level-3 group is to the screen (worth a persistent tab switcher) — it is not evidence the sidebar itself can't render 3 levels, and it is not the default for every 3-level branch. Don't apply it to `Thư viện`'s two expandable nodes just because `Pháp luật` did it; only make this trade when the screen is actually built around switching between those specific siblings.
- Do it fully or not at all: if a branch is truncated, remove its level-3 nodes from that screen's sidebar tree entirely (no dead expand arrow, no orphaned leaves) and add the equivalent `Tabs` — don't leave both a sidebar level-3 and a duplicate tab bar for the same siblings.
