# Drawer
Right-side sliding panel for viewing one record's full detail without leaving the list screen — source at `components/overlay/Drawer/`.
- Anchored to the right edge, full height, slides in via `translateX` (never a centered/scale-in entrance like `Modal`) — same dim backdrop treatment as `Modal`, just repositioned.
- **Click-outside-to-close**: clicking the dimmed backdrop closes the drawer; clicking anywhere inside the panel does not. Implemented as a single `e.target === e.currentTarget` check on the backdrop's own click handler (see `Drawer.jsx`) — not `stopPropagation` on the panel — so the same technique works identically whether the drawer is a React component or hand-authored `.dc.html` markup (`DanhSachChuongTrinh.dc.html`'s `closeDrawerBackdrop` mirrors this exactly).
- **Width: `50vw`** (half the viewport) by default — updated 2026-07-31, was a fixed 720px. Floored at `480px` (`min-width`) so it doesn't get too cramped on narrow viewports, capped at `95vw` same as `Modal`. Override via the `width` prop for a screen that genuinely needs a different proportion; don't hardcode a pixel width as the default going forward.
- Header: title left (bold 16px, conventionally `"{Mã} - {Tên}"`, e.g. `"CT_123 - Kiểm toán hoạt động CNTT"`) + **two** icon buttons right — `open_in_full` (expand) then a close `✕`, in that order. This differs from `Modal`, which has a single bare close affordance.
  - **`badge` (optional, added 2026-08-24)**: an optional status `Badge`, same title-row group as the title (title + badge share one flex block, the two icon buttons stay a separate group on the right) — mirrors `PageHeader`'s own `badge` prop exactly (see `references/components/layout/pageheader.md`), same placement ("Tương tự như header trang chi tiết" — the same convention as a detail page's header) and same `size="large"` (per `references/components/display/badge-tag.md`'s "Size by placement" section — `Badge`'s own default, no need to pass `size` explicitly). Pass it when the record the `Drawer` previews carries a single workflow status (Đã duyệt / Chờ duyệt / …); omit it for a drawer previewing something without a per-record status. Reference implementation: `drawer.card.html`'s `.dr-badge` ("Đã duyệt" next to "CT_123 - Kiểm toán hoạt động CNTT").
  - `open_in_full`'s `onExpand` navigates to a full-page detail screen for that record — use `templates/ias-xem-chi-tiet/XemChiTiet.dc.html` as the base for that page (added 2026-07-31; back-arrow + title + status `Badge` + `Ý kiến`/`Lịch sử`/`more_vert` header, section-switcher, collapsible `Thông tin chung` + grouped-header detail table cards, centered "Đóng" footer). Wire it as an actual page navigation (`window.location.href` to the sibling template file), not a same-page state swap — the Drawer and the detail page are two separate `.dc.html` files, same as any other cross-template link in this project.
- Body: a 2-column grid of `Field` (see `references/components/display/field.md`) for read-only record fields — wraps to additional rows of 2, partial last row stays left-aligned. Not a fixed/closed field set like `FilterCard`'s grid — field count and labels follow whatever columns the source `Table` row has. Updated 2026-07-31: previously an ad-hoc 13px-bold-value style unique to `Drawer`; now uses `Field`'s canonical spec (12px/500 label, 14px/400 value, bottom divider) so `Drawer` and "Xem chi tiết" detail pages render fields identically.
- **Body may also include a table section below the field grid** (added 2026-08-21) — e.g. a related/cross-reference records list for the record being previewed. Content shape (title requirement is now governed by the multi-section rule directly below, not repeated here):
  1. **The table itself must be the real `Table` component** (`components/data/Table`) — never a bespoke `<table>`/`.modal-table` reimplementation. Same rule as `DCard`'s body content, applied here because `Drawer`'s body is the same kind of flexible content slot.
  2. **The table hugs its natural content height — no `max-height`/`overflow` of its own** (corrected 2026-08-21, reversing an earlier version of this rule that let it bound to `max-height:220px` and scroll internally). `.dr-body` is already `Drawer`'s one scroll region (`overflow-y:auto`); a table section with its own nested scrollbox on top of that is the same double-scroll anti-pattern already fixed on the main page (`.content`/`.table-wrap`, see `references/components/data/table.md`) — a second, independently-scrolling box buried inside the one that's already scrolling. Let a long cross-reference list simply make the whole drawer body taller/scroll further, exactly like the field grid above it.
  3. **Table section toolbar (added 2026-08-26): every table section gets a `ToolbarSimple` directly under its `DrSectionTitle`, above the table itself** — same fixed left→right anatomy as the page-level `ToolbarSimple` (`references/components/data/toolbarsimple.md`): search input → "Tìm kiếm" → "Tìm kiếm nâng cao" (swaps to a compact `FilterCard`-style field row scoped to that section's own columns, not the page's `FilterCard`) → trailing "Cài đặt bảng" (`ColumnPicker`, scoped to that section's own columns — see `references/components/data/columnpicker.md`'s rules, including "every option must render a real column"). Render it at `.btn-sm`/`.btn-icon-sm` scale (32px controls), not the full 40px page-level scale — a Drawer section is a denser context than a page toolbar. Skip it only when the table section's own row/column count is small enough that search and column config add no value (a fixed 2-3 column, always-short list) — the default assumption is to include it. Reference implementation: Mapping NVTT's own cross-reference table sections (`mapCrossToolbarHTML`/`mapCrossRefTableOnly` in `Mapping NVTT.html`), mirrored in this component's own `drawer.card.html` sample ("Đơn vị liên quan" section).
- **Multi-section title rule (added 2026-08-21): once the body has ≥2 sections, every section gets its own title — including the record's own `Field` grid, which stays title-less only when it's the sole section.** A single-section drawer (just the record's fields, no table below — e.g. `DanhSachChuongTrinh.dc.html`'s "Chương trình" drawer) keeps rendering the field grid directly, no title needed. The moment a second section is added (a table, or a second field-group), the first section retroactively needs a title too — an untitled field-grid sitting next to a titled table section is an inconsistent, half-labeled layout, not a valid end state.
  - **Section unit**: `.dr-section` — an optional `DrSectionTitle` (`components/overlay/DrSectionTitle/`, see its own rule at `references/components/overlay/dr-section-title.md`) followed by its content (`.dr-grid` of `Field`s, or a `Table`). Stack sections vertically with the body's own gap (24px) between them, same spacing whether the section is fields or a table.
  - **One uniform title component for every section**, field-grid or table alike — `DrSectionTitle` (title + brand accent bar, optional dot-less count `Badge`; updated 2026-08-21, supersedes an earlier plain-`11px` caption draft of this rule). Don't give the field-grid's title a different treatment than the table sections' — same "no empty state" instinct as `DCard`'s mandatory `d-card-header` (`references/components/display/dcard.md`), just one consistent component here rather than DCard's own header-row treatment.
  - **Title text for the field-grid section**: infer it the same way as `DCard`'s title-inference rule (`references/components/display/dcard.md`) — `"Thông tin " + <entity/section name>` (e.g. `"Thông tin chương trình"` for a "Chương trình" record).
  - Reference implementation: `drawer.card.html` (2 sections: "Thông tin chương trình" field-grid + "Đơn vị liên quan" table) and Mapping NVTT's `Drawer` in `Mapping NVTT.html` (`mapOpenDrawer` — 3 sections: the anchor record's own fields + one titled `Table` section per related group, each built via the shared `mapCrossRefTableOnly`/title helpers rather than duplicating table markup per section).
- Footer: same order rule as `Modal`/`Card` (secondary left, primary right) — often just a single `outline` "Đóng" when the drawer is read-only with no save action.
- **Row trigger**: opened from a `Table` row via a `keyboard_double_arrow_right` icon button placed **near the front of the row, immediately after the primary mã/identity column** (not a trailing last column — see the placement rule and auto-placement heuristic in `references/components/data/table.md`) — this is a third accepted row-action pattern alongside text-link and `more_vert` overflow, used when the row's primary action is "view full detail inline" rather than navigate away or open a menu. Still mutually exclusive with the other two per row — pick one.
